= Live task checks

Slurm-web can display structured checks emitted independently by every task in a job.
Checks are delivered to the browser as Server-Sent Events (SSE) and remain available as
a snapshot after the job finishes.

== Emit a check

Install `contrib/slurm-check` on compute nodes and make a shared directory available to
the Slurm-web agent at `/mnt/ai-data/.slurm-web/checks`.

[source,console]
----
$ slurm-check running load-model "Load model" --progress 25 \
    --message "Loading shard 7/29"
$ slurm-check passed load-model "Load model" --duration-ms 31042 \
    --message "29 shards loaded"
----

The command reads `SLURM_JOB_ID`, `SLURM_STEP_ID`, `SLURM_PROCID` and
`SLURMD_NODENAME`. These values can also be specified explicitly with `--job`,
`--step`, `--task` and `--node` for testing.

Each task writes its own append-only JSONL file:

[source,text]
----
<root>/<job>/<step>/task-<rank>.jsonl
----

This avoids concurrent append operations from multiple compute nodes. Supported states
are `queued`, `running`, `passed`, `failed`, `warning`, `skipped` and `cancelled`.
Running checks without an update for 15 seconds are rendered as `stalled`.

== APIs

The current snapshot is available from:

[source,text]
----
GET /api/agents/<cluster>/job/<job>/checks
----

Incremental updates use a resumable cursor:

[source,text]
----
GET /api/agents/<cluster>/job/<job>/checks/events?cursor=<sequence>
----

The SSE connection emits `check` events and a heartbeat every ten seconds. Container
deployments use Gunicorn `gthread` workers so concurrent event streams do not block
ordinary API requests.
